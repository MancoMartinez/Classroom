### 2026-08-28 · 2. On "none of these issues were occurring until the most recent upgrade"
_inbox/2026-08-28-rcs-28556-ADDENDUM-ESCALACION.md_

Joe Austin's statement is accurate and it names the real trigger. The new URL scheme moved sign in traffic onto `apps.apprissretail.com`, which sits behind the Cloudflare default deny perimeter described in section 5 of the prior comment. That perimeter did not exist on the legacy URL. This is not a session or authentication reconciliation issue. It is a country rule on a perimeter that is new since the migration. State it in exactly those terms if this reaches the customer. Do not use the word migration alone without naming the mechanism, that phrasing is what produced the false explanation on RCS-28175.

### 2026-08-26 · 1. Correction
_inbox/2026-08-26-rcs-28556-COMENTARIO-INTERNO.md_

Support told this customer the blocks were a platform migration side effect, with user session and authentication data reconciling across systems. That statement is wrong. A Cloudflare edge block rejects the request on source IP before it reaches the application, so it never touches the session layer. The customer received that explanation on RCS-28175 on 2026-08-05, then received a second claim on 2026-08-11 that root cause was identified and a hotfix implemented. Joe Austin reopened the same day with "This is not resolved." No change record supports either claim. Do not repeat this explanation on any Vitamin Shoppe ticket.
