## Como se purga la cache del tenant

El Control Panel tiene UI de administracion de cache con inspeccion y purgas manuales, en la
pagina `cache`. Ruta en el repo:
`Sources/UI/Components/src/_react/src/apps/control-panel/pages/cache/`.
Fuente: `brain/markdown/13-appriss-onboarding-base-de-conocimiento.md` Parte IV 4.2 y
`brain/markdown/14-appriss-ingeniería-docs-fuente.md`.

Dos cache distintos y no se mezclan. `Director.ClientCache` guarda lo de cada tenant, incluidos
permisos de usuario y configuracion del cliente. `Director.SystemCache` guarda lo de plataforma,
metadata de conexiones y nombres de bases. Para esto va el del cliente, nunca el de sistema.

Cuatro niveles de invalidacion, de preciso a destructivo:

| Nivel | Alcance |
|---|---|
| `PurgeByKey` | Claves puntuales |
| `PurgeByCategory` | Todo lo etiquetado con una categoria, por ejemplo `User_Permissions` |
| `PurgeAll` | El cache completo de ese tenant. Queda auditado |
| `Nuke` | El ClientCache de todos los tenants. Pide el secreto `CachePurge.NukeAuthenticationKey` |

**Eso es "purgar y no borrar".** Purgar es `PurgeAll` acotado al tenant de GUESS, o
`PurgeByCategory` sobre `User_Permissions` si la UI lo ofrece. Borrar es `Nuke`, que se lleva
todos los clientes por delante. Nunca `Nuke` para esto.

La propagacion entre nodos es automatica. En Azure va por Redis pub/sub, cada nodo aplica la
misma mutacion local. Una sola purga alcanza toda la granja, no hay que repetirla por nodo.

Pasos: Control Panel, pagina cache, elegir el cliente GUESS, purgar el client cache de ese
tenant. Si la pagina no aparece, es el rol. El acceso a cache va con Infrastructure, Engineers y
EngineeringManagers.

Verifica, no asumas. En la transcripcion de una sesion de trabajo de Peyman Motlagh el purge se
corrio y la pantalla siguio sirviendo el valor viejo: *"Why did it not purge?"*, y mas adelante
*"It is cached. That is impossible. You saw me purge my my"*.
`brain/markdown/17-reuniones-prep.md`. Despues de purgar, abre la lista de usuarios del tenant y
confirma que las nueve salen en Locked False.

HIPOTESIS: no esta documentado bajo que clave ni bajo que categoria cae el flag `Locked`. Por
eso el nivel correcto aqui es `PurgeAll` del tenant, que los cubre todos. El costo es cache frio
un rato para GUESS, o sea un bache de rendimiento, no un riesgo de datos.
